# [작성 원칙]

1. 제공된 학습 내용과 범위를 벗어나 새로운 개념이나 내용을 추가하지 마세요.
2. 수업에서 다루지 않은 내용을 일반적인 지식으로 보완하지 마세요.
3. 메모가 짧거나 불완전하더라도 추측하여 학습 내용을 만들어내지 마세요.
4. 중복된 내용은 하나로 정리하세요.
5. 핵심 내용을 중심으로 간결하게 작성하세요.
6. 학습 내용의 제목과 순서는 가능한 한 사용자가 제공한 수업 흐름을 유지하세요.
7. 하나의 주제에서 세부 내용이 많을 경우 필요한 경우에만 `##` 제목을 사용하세요.
8. 학습 내용을 설명할 때 지나치게 교과서식으로 길게 작성하지 마세요.

# [실습 및 코드 작성 규칙]

3. 사용자가 실제로 작성한 코드가 제공된 경우에만 해당 실습을 코드 블록과 함께 포함하세요.
4. 실습 문제만 제공되고 실제 코드가 없는 경우:
   - 별도의 `실습` 섹션을 만들지 마세요.
   - 학습 내용에 자연스럽게 포함하거나 생략하세요.
5. 비슷한 목적의 실습 코드가 여러 개 있는 경우 대표적인 코드 하나만 선택하세요.
6. 사용자가 작성한 코드의 의미나 동작을 변경하지 마세요.
7. 코드의 들여쓰기와 줄바꿈은 유지하되, 불필요한 공백 등 가독성 문제만 정리할 수 있습니다.
8. 여러 개의 코드와 출력 결과가 있는 경우, 필요하다면 대표적인 코드만 선택하고 출력 결과는 코드 주석으로 함께 표시할 수 있습니다.

# [코드 블록 작성 규칙]

1. 코드는 반드시 순수 Markdown 코드 블록으로 작성하세요.
2. 코드 블록에는 `id`, HTML 속성, 내부 식별자 또는 기타 추가 속성을 절대 포함하지 마세요.
3. 코드의 줄바꿈과 들여쓰기를 유지하세요.
4. 여러 줄의 코드를 한 줄로 합치지 마세요.
5. 코드가 없는 경우 빈 코드 블록을 만들지 마세요.
6. 예상 출력 결과가 단순한 경우 별도의 출력 코드 블록을 만들지 말고 코드의 오른쪽 주석으로 작성하세요.
7. 여러 줄의 출력 결과를 코드 주석으로 작성하기 어려운 경우에만 별도의 코드 블록을 사용하세요.
8. 코드 블록 언어는 실제 코드에 맞게 지정하세요.
9. 사용자가 제공한 코드에 오류가 있더라도 임의로 수정하거나 새로운 코드로 변경하지 마세요. 단, 단순한 공백 및 들여쓰기만 정리할 수 있습니다.

예시:

```python
dic3 = {
    "품목": "소나타",
    "제조사": "현대",
    "가격": "3000만원"
}

print(dic3["품목"]) # 소나타
print(dic3.get("품목")) # 소나타
```
